## Profile and root cause

Before the change, the rebuild plan used:

- `Index Scan` on `UQ_Inventory_Movement_Daily_ID`.
- Residual predicates on `Kho_ID`, `San_Pham_ID`, and `Movement_Date`.
- Clustered lookups on `PK_Inventory_Movement_Daily` for `IsValid`, `Total_Receipt`, and `Total_Issue`.
- Estimated scan subtree cost observed at approximately `3.01295` with estimated IO cost `2.20979` in the representative plan.

The actual rebuild predicates are scope-first plus a date suffix in `sp_Inventory_Movement_Rebuild` and `sp_Inventory_Balance_Daily_Rebuild`, while the existing clustered key is date-first: `(Movement_Date, Kho_ID, San_Pham_ID)`. The `ID` unique index was therefore a poor access path.

## Change

Added to `Database/WarehouseModule.Schema.sql`:

```sql
CREATE INDEX IX_Inventory_Movement_Daily_Scope_Date
ON dbo.Inventory_Movement_Daily(Kho_ID, San_Pham_ID, Movement_Date)
INCLUDE (Total_Receipt, Total_Issue, IsValid);
```

After deployment, the representative plan used `Index Seek` on `IX_Inventory_Movement_Daily_Scope_Date` with a scope/date range and no lookup for the selected movement columns. The index contains 730,000 rows, 3,999 used pages, approximately 31.24 MB. The existing chronological clustered key was retained for date-oriented consumers.

## Queue and suffix investigation

Three invalidations for the same scope on 2025-01-01, 2026-07-01, and 2026-12-01 produced three active daily queue rows under the existing `(scope, From_Date)` lifecycle. No queue schema or procedure change was made.

To test whether coalescing those rows was beneficial, five rollback-isolated comparisons were run after the index change:

| Workload | Mean ms | P95 proxy ms |
|---|---:|---:|
| Three separate exact-date rebuilds | 14.407 | 17.026 |
| One coalesced 2025-01-01..2026-12-01 rebuild | 87.287 | 102.023 |

On this representative dataset, coalescing would make this pattern approximately 6.1x slower because the earliest date expands the authoritative ledger and balance suffix work. `Requested_Version`, `Claimed_Version`, `From_Date`, `To_Date`, and the H04/H05 lifecycle were therefore left unchanged. Earliest/latest invalidation semantics were not risked without a positive workload result.

## Snapshot worker concurrency observation

The current snapshot worker uses the session applock resource `InventorySnapshotRebuildWorker`, not a scope-specific resource. A deterministic probe held that resource while a worker for a different `(Kho_ID, San_Pham_ID)` attempted a tick; the worker returned `51304` (`Worker rebuild snapshot đang được xử lý...`). This confirms global serialization by design. No scope-lock refactor was made because it would expand the H04/H05 concurrency and failure-lifecycle surface without a measured M01 requirement.
