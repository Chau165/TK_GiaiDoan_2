# Product XLSX Parser Selection Gate — 2026-10-06

## 1. Executive Summary

**Verdict: `XLSX_PARSER_SELECTED`**  
**Selected parser: ClosedXML 0.105.1** for the future Product XLSX reader.

ClosedXML passed the shared data contract for Telerik-, EPPlus 7.0.5-, and actual Microsoft Excel 16.0-generated fixtures. It exposes formulas, typed dates, leading-zero text, and hidden rows. Telerik passed the Microsoft Excel gate but failed the EPPlus fixture with the reproduced nullable-style exception. ExcelDataReader read all available files, but does not expose formula expressions and returned the cached formula result, which is unsafe for Product Import.

Google Sheets and LibreOffice fixtures are `FIXTURE_NOT_AVAILABLE`; no compatibility claim is made for them. This selection is based on the real producers available in this environment, not the full requested producer universe.

## 7. Cell-Type / Formula Behavior

| Capability | Telerik | ExcelDataReader | ClosedXML / selected reader |
|---|---|---|---|
| Vietnamese Unicode / whitespace | Preserved | Preserved | Preserved |
| Text `00123` | Preserved in Excel fixture; format metadata was blank | Preserved | Preserved as Text; number format exposed |
| Numeric cell | Number | Number | Number (`double`) |
| Date cell | Reported as Number for Excel fixture | DateTime | DateTime |
| Internal blank row | Preserved | Preserved | Preserved |
| Hidden row | Row content is read; hidden metadata not exposed by tested adapter | Hidden metadata exposed | Hidden metadata exposed and returned by Product reader |
| Formula expression | Exposed | Not exposed; returned cached value `2` | Exposed as `FormulaA1`; Product reader sets `Value=null` |
| Stream seek requirement | Non-seekable stream passed | Non-seekable stream failed with `NotSupportedException` | Non-seekable stream passed |
| Memory model | Streaming importer | Sequential reader | Workbook object model; highest observed candidate allocations |

Product Import must reject cells with a non-null `Formula`; it must never consume a cached formula value. The new reader preserves formula metadata and clears the formula cell value, but full row validation is not part of this gate.

## 8. Security / Malformed XLSX Results

| Input | Telerik | ExcelDataReader | ClosedXML raw candidate |
|---|---|---|---|
| Empty | InvalidDataException | HeaderException | FileFormatException |
| Random binary | InvalidDataException | HeaderException | FileFormatException |
| Truncated XLSX | InvalidDataException | InvalidDataException | FileFormatException |
| Missing `SanPham` sheet | Controlled InvalidDataException | Controlled InvalidDataException | Controlled InvalidDataException |
| Missing/duplicate header | Telerik parser threw the reproduced nullable exception on these EPPlus files | Controlled InvalidDataException in common validator | Controlled InvalidDataException in common validator |

`CProduct_Xlsx_Reader` maps ClosedXML parse failures to `InvalidDataException`, requires the exact `SanPham` sheet, copies readable streams without depending on seek/Length, rejects files over 1 MiB, and bounds the product worksheet to 100 data rows plus its header and five columns. It does not validate required header text or decide whether hidden rows should be imported; those remain pipeline validation decisions. The full object model is loaded before worksheet dimension limits are checked, so this test does not establish resistance to every highly compressed hostile archive.

## 10. Telerik Result

Telerik passes its own fixture and the important actual Microsoft Excel fixture, so it is not rejected by the Excel-specific gate. It fails the EPPlus-generated fixture consistently at `XlsxCellImporter.ReadCellStyles()` with `Nullable object must have a value`; on Excel it also reports a date as Number and does not expose the tested hidden-row/number-format metadata. It is not selected for the new Product import path. Existing Telerik functionality remains in place.

## 11. ExcelDataReader Result

It passes the three available producers and has the best observed time/memory profile. It is not selected because the API does not expose formula expressions: the formula cell is returned as cached value `2`, which cannot satisfy the required reject-formula policy without trusting a literal. Its low-level stream API also failed the non-seekable test. No DataSet add-on is used.

## 12. ClosedXML Result

It passes all three available producer fixtures, retains text/date/hidden-row information, and exposes formulas. The selected adapter returns formula cells with `Value=null`, preventing cached values from becoming business data. The object-model memory cost is higher than ExcelDataReader but bounded here by 1 MiB input, 100 data rows, and five columns.

## 13. Selected Parser

**ClosedXML 0.105.1 (MIT).** This is one primary parser for the future Product Import reader. No production fallback chain is introduced.

## 14. Selection Rationale

ClosedXML is the only candidate that passed every available producer fixture while also exposing formulas, preserving expected cell types, and returning controlled adapter errors. Telerik has better observed speed but a reproduced external-producer failure; ExcelDataReader lacks formula visibility. Missing Google Sheets/LibreOffice evidence limits the breadth of the claim but does not overturn the winner among available fixtures.

## 15. Integration Strategy

Added `CProduct_Xlsx_Reader.ReadAsync(Stream, CancellationToken)` under Data_Access. It reads only `SanPham` into raw worksheet/row/cell records, preserves row/column indices, value type, number format, formula, and hidden-row state. Formula values are null. It has no UI, database, permission, transaction, Product DTO, or persistence behavior.
